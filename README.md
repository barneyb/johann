# They're All Named Johann

Johann is a fairly comical attempt at building a programming langauge from scratch. It targets only AArch64, is self-hosted†, and generates _terrible_ assembly codes‡. The goal is to solve [Not Quite Lisp](https://adventofcode.com/2015/day/1), with no assembly in the solution itself nor the compiler which compiles it.

You don't want to use it. You don't want to even look at the source. When a bored coder has a martini (or three...) and decides to single-handedly reinvent much of the past ~60 years of computer science from scratch, nothing good results.

> **Why AArch64?** My employer assigned me a mac, and I wasn't interested in flipping between OSes, so I replaced my personal machine. The funny part is they gave me an `x64` mac - in 2023! - but you can't buy those anymore.

† In this case, both a) all non-assembly source code is written in Johann, and b) no other compiler(s) were used during the implementation of Johann. Usually "self-hosted" only implies the first part, after bootstrapping the v1 compiler in another high-level language.

‡ The codes I didn't hand-code were generated by code I hand-coded. Perhaps recursively. All me, all the way down.

## Building Johann Programs

If your source is in `program.jn`, first compile it with `jnc < program.jn > program.s`. Next, assemble and link with `gcc program.s -o program`. Now you can execute it: `./program`. If you have multiple source files, compile and assemble them separately (with `-c`), and then link the object files into final binary.

I've opted for GCC's assembler (aka GNU GAS) and linker, but not its other goodies. Of course, it's actually Apple's clang, but whatever. Probably could go with a vanilla ARM solution, but "GCC" is already installed and I know how to call it.

Implicit is a command shell that understands redirection. Compilation is always "read from STDIN and write to STDOUT" - you can't use files!

The `Makefile` may provide additional inspiration. It's worth mentioning that my `make` skills are commensurate with my skill coding assembly.

## Source Code

Johann source code is always plain text, encoded with UTF-8, and uses a `.jn` extension by convention. Multibyte characters aren't _forbidden_, but they also don't work. All keywords are case-sensitive (unlike GAS assembly). Comments are introduced with `#` and extend to end of line. Whitespace is not semantic, and braces are used for control flow blocks.

A complete solution for Not Quite Lisp is found in `not_quite_lisp.jn`. Note that this doesn't meet the goal stated above, as the _compiler_ is not yet written in Johann.

Functions are defined with the `fn` keyword. Use `return` to return a value. The entry point for a program is always a function named `main`, which returns an exit code. Unlike C, if you let it fall through the end, you get whatever is left in `X0`; probably not what you want. The return type after the colon is ignored.

```
fn main(): int {
    return 0;
}
```

Conditionals use the `if` keyword and loops use `while`. Parentheses are not permitted around the conditional expression. Braces are required around the body. There is no `else`. Functions are called with a pair of parens, and are passed whatever the last expression evaluated to as their single argument.

```
c = read();
while c > b {
    g = g + 1;
    if c = '(' {
        f = f + 1;
    }
    c = read();
}
```

Compound expressions are not supported, so there is no operator precedence. The five normal arithmetic operators are supported: `+`, `-`, `*`, `/`, and `%`. Three comparisons operators are supported: `<`, `>`, and `=` (not `==`).

Semicolons are required to terminate statements which don't take a block.

Strings and identifiers are capped at seven characters. Variables are uniquely identified by their first character (the rest is ignored), and must start with `a`-`h`. I.e., you get eight cryptic variables. Period.

The `bool`, `char`, and `int` keywords may be used to introduce a variable, but are ignored. There is no typechecking. Pointers may be declared with `*`, but like all type information, is ignored.

String are "null-terminated byte strings". Literals are static, so do not need to be `free`-d. Those constructed dynamically (e.g., via `itoa`) must be `free`-d when you're done.

Integers are signed, but only unsigned literals are supported. If you need a negative, subtract it from zero.

Boolean literals `true` and `false` are recognized as aliases for `1` and `0` respectively. Compiled codes always check against `0`, so any non-`0` value will be considered `true`.

It is my intention for non-pathological programs written with this primitive syntax to remain valid forever. We'll see.

## Standard Library

Johann's standard library is minimal:

* `void free( void* )` - free the allocation pointed to by the passed pointer.
* `char* itoa( int )` - return a string version of the passed int.
* `void print( char* )` - print the passed string to STDOUT.
* `void println( char* )` - print the passed string and a newline to STDOUT.
* `char read( )` - read a single character from STDIN, or -1 to signal EOF.
